# 사용자 맞춤형 격자 러닝코스 추천
## 버전 표기

화면 좌측 상단의 버전은 현재 배포된 앱 화면과 정적 파일의 버전을 함께 나타냅니다.

- 작은 UI 수정, 오류 수정, 문구 수정은 소수점 한 자리씩 올립니다. 예: `v1.0` -> `v1.1`
- 기능, 데이터 구조, 경로 탐색 규칙처럼 큰 변경은 정수 자리를 올립니다. 예: `v1.9` -> `v2.0`
- 새 버전을 배포할 때는 `static/index.html`의 화면 버전과 `styles.css?v=...`, `app.js?v=...`의 숫자를 같은 값으로 맞춥니다.

서울 전역의 250m 격자를 기반으로, 사용자가 고른 날짜·시간·러닝 목적에 맞춰 점수가 높은 격자를 연결하는 인터랙티브 러닝 코스 추천 웹앱입니다. 지도에서 현재 위치를 직접 지정하면, 조건별 점수와 인접 격자 관계를 이용해 코스를 애니메이션으로 보여줍니다.

## 무엇을 할 수 있나요

- 서울 8,730개 250m 격자의 조건별 점수를 지도 색으로 확인합니다.
- 날짜와 시간을 고르면 해당 월·평일/휴일·시간 조건의 점수를 불러옵니다.
- 현재 위치 격자 또는 현재 위치에서 1km 이내 최고 점수 격자에서 출발할 수 있습니다.
- 기본 추천, 회복·초보 러닝, 기록·PB 러닝, 경사 선호 코스, 경관 러닝, Long Run 중 목적을 고를 수 있습니다.
- 완성된 경로에서는 러너 아이콘이 격자 중심을 따라 이동하며, 방문한 격자에 마우스를 올리면 자치구와 행정동을 확인할 수 있습니다.

## 실행 방법

### 1. 의존성 설치

프로젝트 루트에서 한 번 실행합니다.

```powershell
py -3 -m pip install -r requirements.txt
```

### 2. 로컬 실행

```powershell
py -3 -m uvicorn app:app --reload --port 8000
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 이미 8000번 포트를 쓰고 있다면 `--port 8001`처럼 다른 번호를 사용하면 됩니다.

### Render 배포

Render의 Start Command는 아래와 같습니다.

```text
uvicorn app:app --host 0.0.0.0 --port $PORT
```

GitHub의 배포 브랜치에 push하면 같은 Render 주소에 새 버전이 자동 반영됩니다.

## 사용 순서

1. 날짜와 시간, 목표 거리, 출발지, 러닝 유형을 고릅니다.
2. 지도에서 현재 위치가 있는 250m 격자를 클릭합니다. 브라우저 GPS를 사용하지 않고 직접 지정하는 방식입니다.
3. `경로 탐색`을 누릅니다. 필요한 항목이 빠졌다면 화면 중앙 안내에서 미선택 항목을 알려줍니다.
4. 지도에서 점수 분포, 선택 위치, 출발 위치와 추천 경로를 확인합니다.
5. 애니메이션이 끝난 뒤 경로에 포함된 격자에 마우스를 올리면 `자치구 + 행정동`이 표시됩니다. 행정동은 격자 중심점 기준입니다.

## 거리와 경로 규칙

| 목표 거리 | 이동 횟수 | 최대 방문 격자 | 재방문 규칙 |
|---|---:|---:|---|
| 3km | 12회 | 13개 | 방문한 격자는 다시 선택하지 않음 |
| 5km | 20회 | 21개 | 방문한 격자는 다시 선택하지 않음 |
| 10km | 40회 | 41개 | 직전 4개 격자로는 돌아가지 않으며, 더 이전 격자는 감점 후 제한적으로 재방문 가능 |

- 이동 길이는 인접한 격자 중심 간 250m를 기준으로 계산합니다. 실제 도로를 따라 측정한 거리와는 다를 수 있습니다.
- 현재 격자에서 상·우·하·좌 인접 격자의 점수를 비교해 가장 높은 곳으로 이동하는 그리디 방식입니다.
- 동점일 때는 진행 방향을 유지하는 후보를 우선해 불필요한 지그재그를 줄입니다.
- `Long Run`을 고르면 목표 거리는 10km로 자동 고정됩니다.
- 이동 가능한 후보가 없으면 목표 거리 이전이라도 코스를 마치고 사유를 표시합니다.

## 점수와 러닝 유형

서버는 선택한 조건에 맞는 0~100점 요소를 불러와 유형별 가중합으로 최종 점수를 계산합니다.

| 점수 요소 | 의미 |
|---|---|
| Air Quality | 자치구·월·시간별 대기질 적합도 |
| Thermal Comfort | 기온, 습도, 풍속, 강수 기반의 열환경 적합도 |
| Crowd | 격자·시간별 혼잡도 적합도 |
| Green / Shade | 녹지, 수변, 가로수, 그늘과 달리기 가능 보행로 정보 |
| Slope | 평탄함 점수. 경사 선호 코스에서는 반대 방향으로 사용 |
| Convenience | 화장실·음수대 유무 기반 편의 점수 |
| Continuity | 인접 격자 연결 수 기반 연속 주행성 점수 |

- 기본 추천은 대기질, 열환경, 혼잡, 녹지·그늘, 평탄함, 편의시설을 균형 있게 반영합니다.
- 회복·초보 러닝은 평탄함, 낮은 혼잡도, 편의시설 비중이 큽니다.
- 기록·PB 러닝은 평탄함, 낮은 혼잡도, 연속 주행성을 중시합니다.
- 경사 선호 코스는 경사가 큰 격자에 높은 점수를 부여합니다.
- 경관 러닝은 녹지·그늘·수변과 대기질을 중시합니다.
- Long Run은 녹지·그늘, 편의시설, 연속 주행성 비중이 큽니다.

선택 날짜가 토요일·일요일 또는 법정공휴일이면 `Holiday`, 그 외에는 `Workday` 조건의 점수를 사용합니다.

## 데이터 구성

| 경로 | 용도 |
|---|---|
| `data/grid.geojson` | 서울 8,730개 250m 격자, 중심 좌표, 인접 관계 계산용 행·열, 자치구·행정동 표시 정보 |
| `data/runscore_base_service_parquet/` | 월·평일/휴일별 파티션으로 나눈 조건별 요소 점수 |
| `data/continuity_scores.parquet` | 격자별 연속 주행성 점수 |
| `data/admin_dong_join_audit.json` | 2025년 2분기 행정동 경계와 결합한 결과 요약 |

`grid.geojson`의 행정동은 센서스용 행정구역 경계를 사용했습니다. 8,564개는 격자 중심점으로 직접 결합했고, 중심점이 경계 밖에 있는 166개는 격자 면적이 가장 많이 겹치는 행정동으로 배정했습니다. 따라서 화면의 위치명은 상세 도로명 주소가 아니라 격자 중심 기준의 행정구역 정보입니다.

```text
running-course-app/

```

## 한계와 해석 기준

- 이 코스는 실제 도로 네트워크 최단경로가 아니라 250m 격자 인접 관계를 따릅니다.
- 매 단계에서 가장 높은 점수를 고르는 방식이므로, 서울 전체를 대상으로 한 전역 최적 경로를 보장하지는 않습니다.
- 지도 클릭은 현재 위치를 가정한 입력이며 GPS 위치를 자동 수집하지 않습니다.
- 행정동 표시는 격자 중심점 또는 최대 중첩 면적 기준이므로, 행정동 경계에 걸친 격자의 실제 모든 위치를 대표하지는 않습니다.
